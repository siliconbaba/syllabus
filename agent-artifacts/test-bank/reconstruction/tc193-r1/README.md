# TC193 R1 — proposal only

Сохраняются Junior/t-7-3/people_management/standalone/training+assessment/Batch07. Не import-ready, не cumulative acceptance. Production и manifest неизменны. Scope разрешён общим поручением завершить проект, новые уровни/темы/слоты не вводятся.

Новая обязанность: новый сотрудник сам организует разрешённую подготовку без присвоения управленческих полномочий. TC065 — руководитель диагностирует задержку результата другого человека; здесь нет оценки performance и исправления чужого onboarding. TC081/082 — установление причины ухода; TC122 — распределение поддержки после PIP; TC268 — проба leadership с ресурсным ограничением. Различие actor само по себе не доказательство: надо проверить, что strongest reasoning именно ограниченная инициативность и согласование, а не тот же «назначь поддержку и результат».

Предлагаемые конкурирующие стратегии: ждать руководителя с чтением публичных материалов; самостоятельно начать вести релиз для демонстрации пользы; попросить аналитика назначить цели; предложить руководителю план разрешённой подготовки и выполнить доступные шаги. Это skeleton, не финальные A/B/C/D. Junior допускает явную границу полномочий; нельзя выдавать её за Middle. Риск: вариант ключа не должен стать единственным длинным перечислением добродетелей.

Runtime: expectation-management/support оба→stakeholders, engine дедуплицирует категорию (не два независимых evidence). Mapping derive от реального согласования ожиданий и поддержки, не от прежних labels. Требуется независимая проверка metadata и cross-bank authority/initiative analogs. Source прилагается полностью; ссылки на другие главы при необходимости расширить.
