# Системы: путь архитектора · контракт редакции 3

Все новые production-артефакты находятся здесь. Старый курс и его JSON не редактировать. Приложение обновляет основной агент после приёмки. Файлы sources/ только для чтения.

## Общая история

Вымышленная российская компания «Контур доставки» (не связана с брендом Контур) — лучше в тексте называть **«Северный маршрут»**. Она запускает B2B/B2C сервис заказов с доставкой. Начало: небольшая команда, web/mobile, один регион, 500 заказов/сутки, бюджет ограничен. Все количества, ставки и инциденты учебные. Постепенно: транзакционные ошибки, рост чтения, внешние партнёры, несколько регионов, аналитика, ML/AI и платформенная команда. Ни одна технология не обязательна по сюжету: допустимо обоснованно отказаться от неё.

Читатель — опытный PM/Delivery/Release с техническим опытом, желающий глубоко понять механизмы. Не заменять теорию списком вопросов архитектору. Код необязателен, небольшие объяснённые SQL/JSON/псевдокод полезны. Главный объём — объяснения и разобранные примеры. Упражнения короткие и только после объяснения. Без искусственных 2-часовых блоков и обязательного 40-минутного задания.

## Маршрут из 32 глав

Арка 1 «Открыть двери»: 01 Первый заказ и карта системы; 02 Путь запроса и первая граница доверия; 03 Где живёт заказ: модель данных и хранение; 04 Последний товар: транзакции и конкуренция.

Арка 2 «Выдержать внимание»: 05 Почему всё замедлилось: запросы, индексы, планы; 06 Несколько серверов: L4/L7, балансировка, сессии; 07 Витрина против источника истины: кэш; 08 Когда память распределена: Redis, Ignite, отказ и стоимость.

Арка 3 «Связать миры»: 09 Платёж без ответа: API, идемпотентность, сверка; 10 Партнёры говорят по-разному: REST/gRPC/GraphQL/webhooks/batch/ESB; 11 Заказ стал событием: broker/queue/pubsub/Kafka; 12 Длинный заказ: outbox, saga, CQRS, event sourcing и CDC с явными границами.

Арка 4 «Найти и доставить»: 13 Каталог уже не найти: поиск, индексы, ranking, модели NoSQL; 14 На карте появился курьер: геоданные, пространственный индекс и ETA; 15 Кому отдать заказ: matching, маршруты и ограниченные ресурсы; 16 Сообщить об изменении: realtime, chat, notifications, offline, concurrent editing.

Арка 5 «Доверять копиям»: 17 У заказа две копии: replication, consistency, failover; 18 Один регион стал тесен: sharding, partition keys, hot keys и rebalance; 19 Кто имеет право записывать: consensus, quorum, fencing, CAP/PACELC; 20 Площадка исчезла: capacity, backpressure, SLO, DR и восстановление.

Арка 6 «Увидеть другой масштаб»: 21 Отчёт мешает заказам: OLTP/OLAP, ClickHouse, lake/warehouse, ETL/ELT; 22 Мир прислал сигнал: telemetry, event time, time series, IoT/edge; 23 Клиенты прикрепили видео: object storage, upload, media processing, CDN/live; 24 Компания стала платформой для других: SaaS tenancy, workflow, documents, audit.

Арка 7 «Научиться предсказывать»: 25 Предсказать опоздание: ML lifecycle, features, training/serving skew, eval/drift; 26 Ответить по регламенту: LLM, embeddings, RAG, vector/hybrid search; 27 Помощник получил инструменты: agent permissions, injection, approvals, idempotency; 28 Посчитать цену результата: TCO/FinOps/ML unit economics и меры без разрушения SLO.

Арка 8 «Изменяться безопасно»: 29 Команд стало много: styles/DDD, modular monolith vs services, platform/control/data plane; 30 Перенести систему: contracts, expand-migrate-contract, cutover, rollback boundary; 31 Проверить доверие: threat model, privacy, supply chain, observability, documentation; 32 Архитектурный совет: цельная защита, альтернативы и перенос в незнакомый бизнес.

## Требования к содержанию

Для каждой главы ориентир 1400–2200 русских слов теории + разбора + экспедиции (глубина важнее числа). Минимум 5 полноценных разделов, каждый раскрывает механизм, причину и ограничение. 1 подробный worked example; 1 реальная по смыслу экспедиция; 1–2 схемы (на пакет не меньше 12), среди них topology, sequence, data layout и failure timeline, не только линейные блоки. SVG только точные авторские схемы, без внешних ресурсов, script/foreignObject/inline event handler. На схеме не больше 4 участников по горизонтали, подписи читаемы на мобильном через локальный scroll. Вложенный SVG в поле svg не нужен, wrapper рисует интерфейс.

Два checkpoint-вопроса с правдоподобными альтернативами; decision предлагает минимум 2, лучше 3 разумных подхода с ценой. Статусы/баллы в UI являются учебным прохождением, не сертификацией. Теория не скрыта за правильным ответом. Никаких выдуманных «вы работали/вы достигли». Не размазывать одинаковый текст по главам.

Источники: использовать публичные программы курсов как карту, технические гарантии проверять по первичным источникам. Нельзя копировать платные уроки. Реальные корпоративные кейсы явно отделять от вымышленных и привязывать к дате, не выдавать старую публикацию за текущую полную архитектуру. Все ссылки доступны из главы, ядро офлайн. Термины раскрывать при первом локальном употреблении. На границах гарантий писать failure model и условия. Не считать SQL/NoSQL, Redis/Ignite, Kafka/RabbitMQ равнозначными заменами без анализа.
