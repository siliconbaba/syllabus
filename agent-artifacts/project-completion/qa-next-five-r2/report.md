# Проверка второй редакции

Все пять кейсов приняты по содержанию. NF-L01 и NF-I01 закрыты. Повторный выбор по материалу без ключей совпал с ключами. Рецензент знал ключи первой редакции. TC-110 унаследовал приёмку по идентичности байтов.

| Кейс | Что требуется вывести в новой редакции | Выбор |
|---|---|---|
| TC-101 | Обе команды завершаются в R. Журнал возвращает квитанцию, поэтому суммы вычисляются по обоим тарифам, а публикаций в P нет. Флаг позже не влияет на исполнение. Обе перестройки только прибавляют задержку. | A |
| TC-102 | Оба маршрута заканчиваются исполнением в P и пересекаются в M. Перенаправление из M в R сохраняет квитанцию на обоих путях и экономит четыре недели по сравнению с новой границей. | B |
| TC-103 | Для обычной операции достаточно M, но редкая идёт через N и всё равно достигает P. Локальная подмена оставила бы списание. При разрешённом переносе создание общей границы даёт сопоставимые суммы безопасно. | C |
| TC-110 | Принятый исходный объект полностью сохранён. | C |
| TC-111 | Относительно действующей координации B приносит 0. При минимальной вероятности D приносит 12 × ⅓ − 2 = +2 млн ₽. Отказ уже учтён, расходы на согласование возникают при любом исходе. A и C оплачивают перестройку до необходимого мандата. Срок не даёт ценового преимущества раннему контракту. | D |

Проверка семейной подсказки на отдельных маршрутах даёт «M → R» или «M → P» без сведений о том, кто публикует, кто сохраняет квитанцию и где допустима подмена. Без этих сведений маршрут не диктует ответ. Полный текст требует сопоставить охват двух путей, место необратимого действия, момент завершения расчёта и срок доступной изоляции. Требование Senior выполнено. Реальный canary по-прежнему нарушает запрет и не набирает достаточно доплат. У всех siblings одинаковы условия, варианты и расположение маршрутов. Отличаются только две записи трассировки одной переменной.

Сверены также объяснения, которые остались от первой редакции. «Готового shadow-режима нет» в метаданных TC-102 означает отсутствие готовой **изоляции**. Производственная конфигурация зеркала существует, но сейчас обе команды уходят в P. Новый разбор A явно раскрывает это различие. WHEN для B/C указывает условия применимости целого действия, для D требует и достаточного охвата, и допустимого реального исполнения. В TC-111 условие для B о неокупаемости согласования теперь действительно контрфактическое. Оценки DQ и иерархия решений согласуются с изменёнными фактами. Условия не изменили границы с ранее рассмотренными аналогами, предмет источников или полномочия Head. Повторенные варианты семьи не выдают три разных ключа по длине.

Сопоставление с тем же рабочим манифестом не выявило изменений его контракта. Изменены именно четыре разрешённых ID. Пересмотр охватил затронутые тексты, связанные объяснения, слепой выбор, уровень, прочтения конкурентов, семейную переменную и новые признаки подсказки. Источники, аналоговые досье, поля манифеста и право участия наследуются из QA первой редакции по сверенным хешам. Результат Swift PASS привязан к новой сумме пакета в validation-summary.json. Допуск к импорту и заморозка остаются отдельными этапами.
